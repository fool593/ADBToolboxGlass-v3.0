## 零、第四轮反馈的 4 个 bug：根因与修法

| # | 你反馈的现象 | 真实根因 | 修法 |
|---|---|---|---|
| 1 | Shizuku 连上了，界面却不显示"已连接" | 每个页面各自在 `LaunchedEffect(Unit)` 里**只查一次**，进页面时没连上就永远显示"未连接"；切到 Shizuku 授权再回来也不会重查。另外"服务在跑但没授权"和"没启动"被显示成同一句话 | Shizuku 状态改为**全局唯一数据源**，统一检测；**应用回到前台 / 拿到授权回调 / 每次回到首页**都会重查。并且拆成三态如实显示：已连接 / **Shizuku 已启动，未授权给本应用** / 未连接 |
| 2 | 退出应用后主题失效，得重新点一次主题才生效 | 重启时只恢复了"选了哪个主题"，**指望 SharedPreferences 里存的正好是主题那套玻璃参数**。两者一旦不一致（旧版本升级上来的配置、上次保存时机不对），就会出现"主题选中了但界面没变" | 启动时**先把该主题的参数写进配置，再逐项用已保存值覆盖**：用户手动调过的项以用户为准，没调过的项一定是主题值 —— 主题不可能再"丢"。另外自动套用的国庆主题当次就落盘 |
| 3 | 液态玻璃没覆盖到全部按钮，比如 ADB 插件的 "+" 像一张图片、没有交互 | 一些可点控件只画了一层**静态色块**（`drawBackdrop` + `onDrawSurface` 画死颜色 + `Highlight.Plain`），没有 `InteractiveHighlight`，所以既没有玻璃折射也没有按下光斑/缩放 | 全仓审计 27 个界面文件、16 处可点控件，把 **10 处**"可点但不是液态玻璃"的控件改成 `liquidGlassItem`（自带模糊/折射/按下光斑/缩放/边缘高光），含插件 "+"、插件启用开关、终端快捷命令、Root 方案选择行、体检"执行修复"、主题配色行、性能页勾选框、华为页勾选框/分组头、玻璃底色圆点等。插件开关还顺手做了平滑滑块 + 轨道变色（原来是瞬间跳位） |
| 4 | 系统应用权限页的胶囊（开关）**点一下没反应，要长按并拖动**才切换 | `LiquidToggle` 用 `didDrag = dragAmount.x != 0f` 判断"算不算拖动"—— **1 像素横向抖动就算拖动**；而手势层没有 touch slop 过滤。真机按下抬起必然有 1~3px 抖动 → 被判成拖动 → 拖了几像素没过半程 → 回弹原侧 → 状态不变，表现为"单击无效"。另外手势只挂在 27dp 的圆钮上，**点 51×31 的胶囊本体完全没反应** | 用 `viewConfiguration.touchSlop` + 累计位移判定是否真的拖动（未超 slop 一律算单击）；手势与 `Role.Switch` 从圆钮移到整个胶囊。单击切换、拖动跟手都正常，且一次手势只切换一次 |

## 一、安装

```
adb install -r androidApp\build\outputs\apk\debug\androidApp-debug.apk
```

或者把 APK 拷进手机直接点安装。

注意：这是 debug 签名的包。如果手机上已经装了用**别的签名**编译的同名应用，会报
`INSTALL_FAILED_UPDATE_INCOMPATIBLE`，需要先卸载旧包（旧包数据会一并清除）。

| 主题 | 主色 | 玻璃与手感 |
|---|---|---|
| 经典 | `#0088FF` | 与原版完全一致，白色 15% 玻璃、白辉光、圆角 0.5。不想变样就留在这个。 |

主题不是换一张皮。它会直接写进全局液态玻璃配置，切换后下面这些都跟着变：

- 玻璃叠加色 `glassColor`
- 长按边缘发光：颜色 / 强度 / 光晕大小、边缘折射量
- 卡片圆角、基础圆角、全局渲染强度
- 底部导航胶囊指示器颜色（否则蓝胶囊配红主题会很突兀）
- 首页快捷入口、性能加速、手机体检、华为深度优化四个页面的强调色

几个具体的行为：

- **国庆期间免设置**：10 月 1 日—7 日**全新安装**（从未选过主题、且没有任何旧版配色记录）
  首次启动自动套用国庆主题。老版本升级上来的用户配色不会被改动；手动选过一次主题后，程序不再干预。
- **国庆横幅**：选中"国庆"主题时首页出现一条横幅，左侧是标准五星红旗图案。
  它不是素材图，而是按国旗标准 30×20 坐标用路径画的：大星中心 (5,5) 半径 3，
  四颗小星中心 (10,2) / (12,4) / (12,7) / (10,9) 半径 1，每颗小星的角尖指向大星中心。
  因此任何控件尺寸下都不会画歪、不会糊。
- 主题参数仍可在"液态玻璃调节"里继续微调，手动改动会覆盖主题默认值；
  重新点一次主题即恢复该主题的标准值。
- 主题选择会落盘（SharedPreferences），下次启动保持。

## 三、华为深度优化（首页 → 华为深度优化）

针对 HarmonyOS / EMUI / MagicOS 的华为机型，共 **30 条方法**，分 7 组：

| 分组 | 条数 | 内容 |
|---|---|---|
| 后台与自启 | 4 | 结束全部后台进程、停用系统更新服务、停用统计上报、直达华为"应用启动管理" |
| 内存与缓存 | 5 | 清理全部应用缓存、回收内核页缓存、内存碎片整理、调整 LMK 阈值、关闭 ZRAM |
| 渲染与 GPU | 4 | 动画缩到 0.5x、强制 SkiaGL、降低渲染分辨率、允许非同步帧提交 |
| 性能模式与温控 | 5 | 打开华为性能模式、退出省电模式、固定高性能、CPU 调频切 performance、关闭内核温控 |
| 存储与编译 | 4 | 后台 dexopt、全量 speed-profile 编译、手动 TRIM /data、清理崩溃日志 |
| 网络与待机 | 4 | 关闭始终扫描 WLAN、关闭始终开启移动数据、WLAN 低延迟、TCP 接收窗口 |
| 系统级（需 Root） | 4 | 停用华为应用加速服务、停用华为推送、块设备调度器切 none、提高块设备预读 |

页面提供：设备识别（机型 / EMUI 或 HarmonyOS 版本 / SoC / 内存 / Shizuku、Root、Dhizuku 权限状态）、
一键华为深度优化、仅执行安全项、全选 / 全不选、**验证本机可用性**（逐条跑验证命令并标注
有效 / 无效 / 需权限）、每条方法单独执行、有回滚的执行"恢复"、执行报告（成功数 / 失败数 /
释放内存 / 总耗时）与原始日志，以及"在终端中打开"。

设计上刻意守住的几条：

- 每条都是真实命令，命令与验证命令原文都能在卡片里展开看到，失败时显示真实 stderr，不吞错误。
- 每条命令末尾都带唯一标记 `HWM_<ID>_DONE`，并在关键条目里附加状态回读行
  （`FreeRAM=`、`state=`、`data=`、`cached=`），所以"到底有没有生效"是看得见的。
- 高风险 5 条（LMK 阈值、关闭 ZRAM、CPU performance 调频、关闭内核温控、停用华为应用加速服务）
  默认不勾选，必须走二次确认；8 条不可逆的方法会明确标出。
- 没有禁用任何通讯、支付、系统 UI、桌面、输入法、华为账号、推送核心之外的**关键**系统包；
  唯一会丢数据的是"清理崩溃日志"（丢的是崩溃现场，已在文档与界面里写明）。
- 进入非华为机型时页面顶部会直接提示"部分接口可能无效，执行结果会如实回报"，不假装能用。

30 条方法的逐条说明（命令 / 验证 / 恢复 / 权限 / 风险 / 适用 ROM / 收益 / 已知限制）
见 `docs/huawei_methods.md`。

### 权限前提（重要）

**30 条方法全部需要 Shizuku 或 Root**（19 条 Shizuku、11 条 Root），没有一条能在普通应用 shell 下生效。
这不是偷懒，而是这些接口（`pm disable-user`、`settings put`、`/proc`、`/sys` 节点）本身就不对普通应用开放。
如果没有 Shizuku / Root，请先在设置页申请 Shizuku 权限，否则页面只能看不能做。

## 四、这次一并修掉的真实故障

| # | 问题 | 为什么会出问题 | 修法 |
|---|---|---|---|

## 六、14 条"不确定"的华为接口

下面这些命令本身写法正确，但**键名、节点或子命令会随 ROM 与内核变化**，所以界面上把它们
放在验证与回读之后：先看"验证本机可用性"的结果，再看执行后的状态回读，不要只看成功与否。

`power_mode_on`（`hw_power_mode` / `hw_performance_mode` 键名随版本变，高版本可能已改成应用级性能模式）、
`net_wifi_low_latency`（`cmd wifi` 子命令与驱动支持都不确定）、
`net_tcp_rwnd`（属性默认由内核内置值提供，`getprop` 可能读空）、
`gpu_skiagl`（Android 12+ 上本来就是默认值，等于无操作，只在 EMUI 10/11 有意义）、
`gpu_sf_latch`（SurfaceFlinger 调试属性，Google 未承诺长期保留）、
`mem_lmk_tune`（Android 11+ 改用用户态 lmkd，节点通常不存在）、
`power_thermal_off`（华为温控多在用户态，可能绕过内核 thermal zone）、
`power_gov_performance`（部分内核只允许 `schedutil`）、
`sys_io_scheduler`（部分内核没有 `none`，UFS 多队列默认已是 `none`）、
`sys_readahead`（随机读为主时可能是负收益）、
`bg_disable_stats`（`com.huawei.bd` 的职责随 ROM 有差异）、
`bg_autostart_page`（两个 Activity 名是经验值，可能随版本改）、
`bg_kill_all`（OEM 可能裁剪 `am help` 的文本，导致验证出现假阴性）、
`mem_zram_off`（swap 设备名不一定是 `zram0`，恢复可能需重启）。

另外有 3 条验证是基于 ROM 帮助文本探测的（`am help`、`cmd package help`、`cmd power help` / `cmd wifi`），
在被 OEM 裁剪帮助文本的 ROM 上会显示"无效"但命令其实可用——这种时候以执行后的状态回读为准。

## 七、第五轮反馈的修复与新增

### 1. 主题不再"退出就丢"（这次是彻底修死）
你反馈的现象很关键：**首页红五星横幅还在（说明主题选中状态是保存住了），但玻璃颜色和高光回到了原来那套**。
说明"选了哪个主题"存住了，"主题那套玻璃参数"没生效——旧写法指望存档里正好存着主题参数，两者一旦不一致就会这样。

现在的规则是确定的，不再依赖"存档值恰好等于主题值"：

- 新增落盘标记 `app_theme_user_overrode`（用户是否在「液态玻璃调节」里手动改过玻璃参数）。
- 启动顺序改为：先恢复全部存档 → **最后再判定**——选了主题且没手动改过 → **以主题为准并立即回写存档**；
  手动改过（并点了保存）→ 以你的调整为准备，主题不再强行覆盖。
- 选主题时该标记自动清零；「液态玻璃调节」里任何一处改动都会把它置位（54 个改动点已全部覆盖）。

结论：**保存主题之后，无论退出应用、杀进程还是重启手机，主题效果都会保留**；只有你自己改过玻璃参数才会让主题不再覆盖。

### 2. 机型独立分类 + Root / ADB 分行
- 新增「机型分类优化」页（首页入口）：小米/红米、华为、荣耀、OPPO、realme、一加、vivo、iQOO、
  三星、魅族、努比亚·红魔、华硕 ROG、索尼、摩托罗拉、Pixel，**每个品牌一张独立卡片、独立入口、独立条数**，
  顶部再有一个「全机型通用」入口。条数全部由数据层实时计算，界面不写死。
- 性能页与体检页的条目**按提权通道分成两块**：「Root 专属」与「ADB / Shizuku 可用」，
  各有标题、条数、全选/清空；缺哪条通道会在组标题上直接标注，组内条目显示"因缺提权不可用"，而不是点了没反应。
- 通用项共 52 条（Root 18 / ADB 34）。
- 说明一处如实告知：vivo 与 iQOO、OPPO / realme / 一加、华为与荣耀目前**入口完全独立、计数独立、筛选独立**，
  但底层指令集是各自共用的（数据层原本就是共用）。要真正拆到"每个品牌一套不同命令"，
  需要为它们单独建条并逐条验证真机有效性——那属于后续工作，我没有为了凑数编造命令。

### 3. 游戏帧率（全机型，华为需要 ADB）
新增「游戏帧率」页（首页入口）。它做的是一件真事：把**显示刷新率**固定到你选的档位，游戏与所有应用都按该帧率跑。

两条写入通道，按机型自动选择——这正是"华为需要 ADB 权限、其余机型不需要"的技术原因：

| 机型 | 通道 | 是否需要 ADB |
|---|---|---|
| 非华为 / 荣耀 | 应用自身的「修改系统设置」(`WRITE_SETTINGS`) 权限直写 `peak_refresh_rate` / `min_refresh_rate` / `user_refresh_rate` | **不需要**，只需在系统设置里授予该权限（页面有一键跳转） |
| 华为 / 荣耀 | 厂商把刷新率键挪到了应用写不到的位置，必须 `settings put`，即 Shizuku(ADB) 或 Root | **需要** |

- 可选档位来自**本机真实支持的刷新率列表**，不会给出本机做不到的选项。
- 写入后**真实回读**当前刷新率并如实显示；部分机型需要熄屏再亮或切后台才真正切换，界面已说明。
- 没有"只改某个游戏"的开关：AOSP 并未开放按单个应用改刷新率的接口，所以不做假选项。

### 4. 模块自带 UI：有才显示按钮
- Root 模块与 ADB 插件都以**真实扫描**（webroot / webui 入口 html）判断模块是否自带界面。
- **只有真的带 UI 才显示「打开界面」按钮**；没有就不显示，不做"显示了但点了报错"的假按钮。
- 打开时会以 Root 身份把 webroot 拷到应用私有目录再交给 WebView 加载；
  失败按原因分开提示（没有 UI 文件 / 需要 Root / 拷贝失败 / 异常），并把原始细节一并显示。

### 5. Shizuku 状态如实显示（三态）
连接上了却不显示"已连接"，是因为每个页面各自只查一次、之后永不刷新。
现在 Shizuku 状态是全局单一数据源，**回到前台 / 授权回调 / 每次回首页**都会重查；并且拆成三态：
已连接 / **Shizuku 已启动但未授权给本应用** / 未连接 —— 以前"启动了但没授权"被笼统显示成"未连接"，容易误判。

### 6. 插件 / 模块安装失败会给出具体原因
安装路径重写为：解压结构识别更全（module.prop 不在根目录、Magisk 的 update-binary、KSU 的 customize.sh 等）、
写入后**回读校验**（确认模块真的出现在列表里）、失败按原因分类回报，例如：
压缩包无效、缺少安装脚本、模块 id 含非法字符、**zip 越界路径已拒绝解压**、无 Root / 未授权、
`/data/adb` 只读、暂存失败、校验失败、推送失败等，并附原始 stderr。
